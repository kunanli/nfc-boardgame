# NFC 桌遊：組隊冒險・搶尾刀奪寶

用 **NFC 晶片 + 空白卡片** 做的競爭型桌遊創意，搭配一個 **服務端系統** 當裁判做所有判定。
本 repo 是「最小可玩單位」的原型與測試，聚焦三件事：**規則、目標、玩家**。

## 遊戲一句話

> 一群冒險者「組隊」進同一個地城打同一批怪，但彼此是對手——
> **誰對怪物打出最後一擊（尾刀）就獨得該怪的賞金**，最終王倒下時，**金幣最多的人獲勝**。

合作的外皮、競爭的內核：你需要別人幫忙磨血條，但賞金只給補刀的人。

## NFC 硬體構想

| 元件 | 作用 |
| --- | --- |
| **NFC 晶片** | 只存一個 **UID**（卡片身分證），不存數值 |
| **空白卡片** | 貼上晶片就是一張卡；卡面可自行手繪 / 貼圖 |
| **讀卡機** | 全桌共用一台，玩家「刷卡」就是把 UID 送給服務端 |
| **服務端** | 唯一裁判：查 UID → 判斷這張卡是什麼、依當前狀態決定發生什麼事 |

**為什麼數值不寫在晶片上？** 因為卡的「意義」全放在服務端 `cards.json`：

- 空白卡可以隨時被重新定義（改版、平衡性調整不用重印卡）
- 玩家無法竄改卡片數值（防作弊）
- 一張晶片今天是哥布林、改天可以是龍——換資料即可

真實流程：`讀卡機讀到 UID → POST /tap → 服務端判定 → 回傳結果給前端顯示`。

## 三個最小單位

### 玩家（players）
每人持一張 **英雄卡**，刷卡加入隊伍（LOBBY 階段）。各自累積金幣、各自計分。

### 規則（rules）——服務端判定的核心
1. **翻怪**：刷一張怪物卡，把牠擺上桌（同時只能有一隻）。
2. **輪流出手**：照座位順序，輪到你才能刷自己的英雄卡砍一刀（服務端擋亂序刷卡）。
3. **搶尾刀**：把怪物 HP 砍到 0 的人 = 尾刀者，**獨得該怪全部賞金**。
4. **怪物反擊**：沒補死牠，怪物就反擊出手者。
5. **撤退懲罰**：英雄被打倒 → 撤退回城、**滿血復活但扣 3 金幣**（懲罰貪刀送頭）。

### 目標（goal）
打倒 **最終王（boss）** 時遊戲結束，**金幣最多者獲勝**。
boss 賞金很高，所以補到 boss 通常會贏——但如果有人一路囤金，補到 boss 也可能被反超，這就是張力所在。

## 專案結構

```
nfc-boardgame/
├── cards.json          # NFC UID → 卡片定義（英雄 / 怪物 / 道具）
├── game/
│   ├── models.py       # Hero / Monster / Player 領域模型
│   ├── cards.py        # CardDB：UID 查表、產生物件
│   └── engine.py       # 規則引擎 / 裁判，單一入口 Game.tap(uid)
├── server.py           # 服務端：純標準庫 HTTP，模擬讀卡機送 UID
├── demo.py             # 不需硬體，命令列跑完整一局
├── index.html          # 純瀏覽器版（GitHub Pages 首頁），內嵌同一套規則
├── .nojekyll           # 讓 GitHub Pages 直接出靜態檔
└── tests/
    ├── test_engine.py  # Python 引擎：規則 / 目標 / 玩家 單元測試
    ├── test_web.mjs    # JS 引擎邏輯測試（與 Python 版一致）
    └── test_browser.mjs# 真瀏覽器端對端：模擬碰卡開網址
```

零第三方依賴，Python 3.8+ 即可。

## 快速開始

```bash
# 1. 跑測試（規則、目標、玩家）
python3 -m unittest discover -s tests -v

# 2. 看一場自動示範（最有感）
python3 demo.py

# 3. 互動模式：自己輸入卡片別名當作刷卡
python3 demo.py -i

# 4. 啟動服務端（模擬真實讀卡機接 HTTP）
python3 server.py
```

### 服務端 API

| 方法 | 路徑 | 說明 |
| --- | --- | --- |
| POST | `/tap` `{"uid": "..."}` | 刷一張卡（依階段自動判定：加入 / 翻怪 / 出手 / 用道具） |
| POST | `/start` | 主持人結束組隊、開始冒險 |
| POST | `/reset` | 重開一局 |
| GET | `/state` | 查詢戰況（階段、輪到誰、桌上怪物、排行榜） |
| GET | `/cards` | 列出所有已登錄卡片 |

```bash
curl -s -XPOST localhost:8080/tap   -d '{"uid":"04A1B2C3"}'   # 戰士加入
curl -s -XPOST localhost:8080/start -d '{}'                    # 開始
curl -s -XPOST localhost:8080/tap   -d '{"uid":"04D0E0F1"}'   # 翻出哥布林
curl -s -XPOST localhost:8080/tap   -d '{"uid":"04A1B2C3"}'   # 戰士出手
curl -s localhost:8080/state
```

## 🚀 最推薦：GitHub Pages（iPhone 專用，不需電腦、不需服務端）

判定邏輯已改寫成純瀏覽器 JavaScript（根目錄 `index.html`），可直接掛在 GitHub Pages，
**免電腦、免服務端、免額外註冊**。遊戲狀態存在手機瀏覽器（localStorage），碰卡就判定。

### 一次性設定
1. **開啟 Pages**：GitHub repo → **Settings → Pages** → Source 選 **Deploy from a branch**
   → Branch 選 `main`、資料夾選 **`/ (root)`** → Save。等一兩分鐘。
2. 頁面網址會是 `https://<你的帳號>.github.io/nfc-boardgame/`。
3. **iPhone 開設定頁**：Safari 打開 `https://<你的帳號>.github.io/nfc-boardgame/?view=setup`，
   會列出每張卡要寫入的網址（可一鍵複製）。
4. **寫卡**：App Store 免費下載 **NFC Tools** → Write → Add a record → **URL/URI** →
   貼上某張卡的網址 → Write，iPhone 靠上那張 NTAG213 貼片。每張卡寫一次。

### 開始玩
- iPhone 碰**英雄卡** → 跳通知點開 → 加入隊伍（每人一張）。
- 網頁上按「**開始冒險**」。
- 碰**怪物卡**翻出怪物 → 輪到的人碰**自己的英雄卡**出手，誰補刀誰奪寶。
- 最終王（巨龍）倒下時，金幣最多的人獲勝。

> NTAG213（144 byte、13.56MHz、ISO 14443A）存一個網址綽綽有餘，iPhone 17 會自動感應開網址。
> 這支手機當「公用讀卡機」輪流傳著碰即可；狀態存在這支手機的瀏覽器裡。

## 用 iPhone 實際玩（自己電腦當服務端，Python 版）

原理：**把一個網址寫進每張卡的 NFC 貼片**，iPhone 碰到就自動開網址 → 服務端判定 → 顯示結果。
卡的「數值」還是在服務端，貼片裡只放 `.../tap?uid=XXXX`。

1. **電腦跑服務端**（電腦要和 iPhone 連同一個 WiFi）：
   ```bash
   python3 server.py
   ```
   啟動訊息會印出「手機同 WiFi 看」的網址，例如 `http://192.168.0.10:8080`。
2. **iPhone 開設定頁**：Safari 打開 `http://<那個IP>:8080/setup`，會列出每張卡要寫的完整網址。
3. **寫卡**：App Store 免費下載 **NFC Tools** → Write → Add a record → URL → 貼上某張卡的網址 → Write，把 iPhone 靠上那張卡的貼片。每張卡寫一次。
4. **投影儀表板**：找一台裝置（電腦或另一支手機）開 `http://<IP>:8080/`，會即時顯示戰況、輪到誰、排行榜（每 2 秒自動刷新）。
5. **開始玩**：iPhone 碰英雄卡加入 → 碰畫面上「開始冒險」→ 碰怪物卡翻怪 → 輪到的人碰自己英雄卡出手。每次碰卡，iPhone 上方會跳通知，點一下就看到判定結果。

> 想更順（碰卡不跳 Safari、直接出結果通知）：用 iPhone 內建「捷徑」App 的 NFC 自動化，
> 動作設「取得 `.../tap?uid=XXXX` 的內容」。設定較繁瑣，但玩起來更貼近真桌遊。

## 接真實硬體怎麼做

服務端已經把「刷卡」抽象成 `POST /tap {"uid": ...}`，所以硬體端只要：

- **手機**：用支援 NFC 的手機讀晶片 UID，App 發 HTTP 給服務端。
- **樹莓派 + PN532/RC522 讀卡機**：Python 讀到 UID 後直接 `import game.engine` 或打 `/tap`。

引擎完全不管硬體，換讀卡方式不用動遊戲邏輯。

## 設計取捨

- **判定全在服務端**：客戶端只負責讀 UID + 顯示，防作弊、易改版。
- **戰鬥無隨機性**：目前是純數值結算，方便測試與教學；要加骰子只需在 `resolve` 出手處注入一個可注入的亂數源。
- **最小單位優先**：先把「規則 / 目標 / 玩家」跑通並有測試覆蓋，之後再加職業技能、事件卡、地圖移動等。
